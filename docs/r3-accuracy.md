# R3 accuracy investigation and reviewed CPU correction

R3 fixes a concrete 65C816 addressing defect and adds independent functional
programs and an isolated DSP input-timeline test. It does **not** close the 18
whole-console audio failures or certify an original SNES motherboard. The original
M8/M9 reference manifests, audio/video goldens and archived reports are unchanged.

## 65C816 emulation indexed-indirect pointer

The unchanged [gilyon v1.4 CPU test](https://github.com/gilyon/snes-tests/tree/5ecdf555da920f0bd7b157542141965a8120186d)
failed test `$0027`: `ADC ($F7,X)`, `E=1`, `D=$011A`, `X=$EE`, `DBR=$7F`.
The pointer low byte is read at `$02FF`; the high byte wraps to `$0200`.
The old shared helper incorrectly read `$0300`. The independently authored
upstream test specifies `A=$1100`, `P=$33`; its unmodified ROM now reaches
`Success`, final test `$0649` (1610 cases).

Only `(direct,X)` receives this emulation exception. Plain `(direct)` and
`(direct),Y` retain their unaligned-D behavior; native mode retains 16-bit pointer
incrementing. The timestamped whole-machine regression checks low/high latches
at master clocks 32/40 and verifies an ADC and a store across 58 save/load
boundaries. No timing constant, APU frequency or DSP arithmetic changed.

The previously pinned SingleStepTests corpus disagrees at 264 `(direct,X)`
emulation page-boundary cases. Raw results remain visible: 246 final-state
mismatches and 264 bus mismatches in the full bus run. The original 5,080,400
vectors and their hashes are unchanged. The default/offline rejection control
uses one separately pinned, verbatim MIT-licensed upstream object in
`testdata/r3-cpu-adjudication-input.json`; its provenance records the exact source
commit, full-source hash and original byte offset. It needs no optional full cache. The separate
`testdata/65816-dp-indexed-quirk.json` contains 264 independently executed pinned
bsnes processor expectations, with original vector hashes, full final registers,
RAM and every bus cycle. Original pins and idle cycles remain unchanged.

**All 264 corrected paths read bytes absent from the sparse original initial-RAM
list.** Supplemental fixtures explicitly define all 24-bit flat RAM as zero before
applying listed bytes and record those additional read addresses. Thus these are
software tests under a documented, completed memory context; they are not 264
new hardware measurements or a claim that the raw corpus supplied those values.
The unchanged gilyon program initializes its own test data independently.

`cpu-full` and `cpu-bus-full` report raw mismatch counts and per-case raw
contradictions separately from approved comparisons. The laboratory's green exit
means the explicitly reviewed contract passed; it does not mean raw agreement.
`tools/65816-dp-reference.py --acquire` rebuilds the pinned external processor in a
separate laboratory executable, never linked into the C# product. There is no
automatic golden update. The reference's separate bank-crossing issue is outside
all 264 supplemental inputs and is explicitly rejected by acquisition.

## Format 9 compatibility

No serialized layout changed. A state before the corrected high-byte read can
resume safely. A previous-core journal that already latched the obsolete
next-page byte cannot be migrated without inventing the missing read or undoing
possible effects. `RestoreContinuation` rejects that precise journal while
`StateSerializer.Load` builds its temporary machine, before worker replacement.
The error asks the user to restart the ROM or load an earlier state.

Fifty real states generated by the unmodified previous core at commit
`c999c7f747ba6e554254e7fa9082ae91357a24ed` are retained with their source/binary
identity. Twelve obsolete ADC/STA journals, including read-hold and pre-store
phases, fail closed; 38 earlier states resume to the corrected exact raw state.
These own-core states are compatibility regressions, not independent CPU oracles.
Completed old architectural states remain architectural states; the loader does
not retroactively repair earlier emulation effects.

## Whole-console audio isolated from DSP arithmetic

A new read-only observation overlay on the unchanged pinned bsnes reference
records executed DSP ticks and only **external input effects**: SMP writes to
shared ARAM and DSP register writes. DSP echo writes are separately recorded as
expected outputs. They are never injected into own RAM. Tick 1 executes phase 0;
phase 27 emits the first pair at tick 28. An event at tick N follows N executed
phases. These epochs come from the source, not alignment searches.

Replaying that input into the unchanged own DSP produces all 89,524 stereo pairs
and all 191,408 timed echo byte writes exactly over 168 fields. This is true in
the separately executed Own-IPL and local-original-IPL probes. Both observed
reference PCM files remain byte-identical to the historical reference probes.
Only the freely licensed Own-IPL timeline is bundled. The manifest identifies
ROM, source commit, retained audio/art/music attribution, replay, frequencies,
power/reset conditions, observer sources, linked objects and executable hashes.

The regression rejects changed expected PCM, changed echo output, a changed
volume-register input, a missing echo output and a chronologically valid KON
input delayed by 64 DSP ticks. The delay is a negative input perturbation,
stable-sorted in time; the unchanged positive trace has no shift or rotation.
An initial 32-tick perturbation of the first KON was ineffective in that key-latch
window and its failed negative-control run is retained. No comparator threshold
or positive output was changed to conceal it.

This isolates the first bsnes discrepancy at pair 88915 away from the DSP's
arithmetic/echo computation **under identical input effects**. It does not prove
that either whole-console scheduler is hardware-correct. Whole-console input
traces already differ in time at event 241 (own tick 51994 versus reference
52003); later pitch/volume writes fall in different phase slots. The first bsnes difference has now been traced further. Its CPU starts ROM
execution after a source-defined 132-clock delay plus a 54-clock interrupt-shaped
reset sequence. Our deterministic API finishes CPU reset before clock zero. In a
strictly laboratory-only experiment, holding the CPU for those 186 master clocks
while APU/PPU continue changes the first CPU port write from clock 1088552 to
1088746, exactly the reference value. At DSP tick 51981, Own IPL `PC=$FFD0`, opcode
`$78` (`CMP $F4,#$CC`) sees `$CC` in the default epoch but still `$00` with the
reference epoch. The latter takes one more poll, then `PC=$FFD7`, opcode `$DA`
(`MOVW $00,YA`) writes at tick 52003 rather than 51994, exactly the reference.
No timer read lies in this causal branch.

That single, source-derived release parameter makes the entire 168-field
**overlapping** PCM sequence match bsnes for both firmware variants in the local
probe. It is not a sample shift or a frequency change. The permanent Own-IPL
`audio-epoch-proof` retains both the default known-red control and the explicit
reference-epoch result, with the PC/opcode/port witnesses. Distinct terminal
capture lengths remain visible. The experiment uses no product profile change;
the default reset epoch remains unchanged because no universal physical
186-master-clock reset duration has been established.
The ares first mismatch is not closed by a bsnes-only isolated timeline.

All 18 original whole-console full-sequence audio differences remain accuracy
failures. Initial 32768-pair agreement is separate. Default APU frequency remains
24,576,000 Hz / 32000 pairs; explicit reference-frequency experiments remain
24,606,720 Hz / 32040 pairs. No sample shifting, tolerance or frequency calibration
turns the red inventory green. Active M8 output now prints `initialAudio` and
`fullOverlapAudio` explicitly, so `initialAudio None` cannot hide a later failure.
The fourth historical M8 adapter snapshot preserves the old output script's exact
bytes; comparisons and all original expectations remain unchanged.

## Published hardware evidence and reset limits

The [additional primary-source ledger](../testdata/r3-published-evidence.json)
pins both checkout-byte and canonical Git-blob identities for the author's [TAStable investigation](https://github.com/rasteri/TAStable/tree/109059a2e352e019050b898738d7615051d6f855).
Its stated scope is a modified SHVC-CPU-01 with SHVC-SOUND. Separate oscillators,
reset-path differences and divider phase undermine universal deterministic
power/reset assumptions. The front-panel and external reset paths differ.
This source does not specify stock VRAM/CGRAM/OAM retention values, provide our
board capture or certify PAL/1CHIP behavior.

Therefore PPU memory clearing on the current deterministic reset API is explicitly
unverified and remains unchanged; APU warm reset already retains RAM and timer
targets. The analytical `-unverified` profiles remain unverified. The original M8
ledger still marks forced-blank contention corruption and analog brightness
transients as absent, and revision-specific early-read/DMA errata as untested.
Published author observations are evidence leads, not newly acquired hardware
traces. No original-hardware acceptance is asserted without board/binary/capture
identities and an observable expected result.
