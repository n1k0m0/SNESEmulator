# Bug audit, October 26, 2026

Reviewed the post-header baseline `7b0cb0a`, including the failed hosted run
[40264231598](https://github.com/n1k0m0/SNESEmulator/actions/runs/40264231598).
The review focused on persistence/recovery, frontend worker handoff, update
validation and shutdown, network framing/presentation, and regression integrity.
It does not claim an exhaustive audit of every instruction or physical hardware.

## Confirmed findings and corrections

### Blocked UI producers survived mailbox disposal

`UiMailbox` disposed its semaphore without completing pending `WaitAsync` calls.
A full mailbox could therefore leave producers waiting after the UI had gone.
Its queued callbacks also remained accessible to a later drain.

The bounded channel now completes writers on disposal and clears queued actions
and status. New posts fail with `ObjectDisposedException`; repeated close is safe.
Callback admission is serialized with close, while invocation runs outside the
gate so background I/O can still publish status. Already admitted work can finish;
reentrant close prevents further callback admission. Capacity and status
coalescing remain bounded.

The new close regression failed on the old implementation with 30 other runtime
groups passing. It now passes. A second regression checks concurrent status
publication from inside a callback and reentrant disposal of queued work.

### Backup-only saves could not reach Manager recovery

The catalog correctly listed `.snessav.bak` when the primary was missing, but
the Manager tried to identify its cartridge by reading the absent primary.
This stopped the UI before previewing or explicitly restoring the valid backup.

`ReadIdentityForReview` may read the backup's identity after a missing, truncated
or invalid primary, and the Manager uses it for cartridge selection. It does not
write or restore files. The normal identity reader/load path stays strict;
complete backup validation and explicit recovery still precede replacement.
Access/permission errors are not hidden by the fallback.

The portable regression reproduced the missing-file exception and now verifies
listing, strict normal reads, nonmutating backup review, exact explicit restore
and rejection of a damaged backup. Its initial fixture-directory scan hit a
different existing stress fixture; that original failed run is retained and the
corrected reproduction uses its own isolated save directory. The actual WPF
Manager smoke also exercises missing-primary review and restoration, in addition
to its existing corrupt-primary case.

### DSP fixture source pins broke after header additions

Both hosted portable jobs stopped at `dsp-reference.py --verify`: its adapter and
generator hashes were implicit fields, so the path-based header inventory missed
them. The narrow pre-push checks had omitted this verifier.

The original DSP adapter and generator are now archived as two more historical
sources, matching the unchanged original fixture hashes. Verification uses those
original bytes; an explicitly requested rebuild still records/checks the actual
current generator and adapter. No fixture was regenerated or expected value
changed. The header checker also verifies these two implicit source pins, so
their omission is caught by the quick check. The archive now has 31 sources.

## Validation and evidence

Local reports are retained under `artifacts/bug-audit/`, including failed
reproductions and corrected results. Before/after reports are separate; the first
mailbox correction run precedes the additional callback-lock regression.
The targeted final runtime gate passes 32 groups; portable Manager passes 17.
The complete solution builds with the existing nullable warning in a distribution
test. The full `python tools/test-lab.py --windows` gate completes successfully
(exit 0, 1,023.375 seconds). It includes all 144 Core groups, 32 runtime groups,
17 portable Manager groups, 23 distribution groups, 35 video groups, all 151
native interaction stages, native persistence/failure probes, nine Windows
Manager groups, 15 Windows integration groups and 24 Windows network groups.
The real WPF Manager smoke passes the new backup-only recovery case. Reports and
previous generic reports are preserved separately under `artifacts/bug-audit/`.

This is a local Windows run against the recorded dirty working tree based on
`7b0cb0a`; it is not a new hosted Linux/Windows CI result. The default CPU gate
checks 2,048 sampled cases and keeps the remaining full-corpus coverage explicitly
unexecuted. Neither the full external corpora nor strict native-hour acceptance
were repeated. The old hosted failures are not relabeled as current successes.

Update metadata/download/installer ownership, bounded state readers, SRAM lease
ordering and network packet/clock validation were inspected without a further
confirmed product defect in this bounded review. Existing regression coverage is
run again; absence of an additional finding is not a correctness certificate.

The documented NTSC/PAL native realtime limits, raw CPU/SPC/chip disagreements
and 18 full-sequence audio accuracy failures remain open. This audit does not
change hardware clocks, state formats, audio samples, acceptance thresholds or
original expected fixtures. See [the laboratory status](test-laboratory.md).
